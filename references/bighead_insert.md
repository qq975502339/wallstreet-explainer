# 人物故事段落：委托 bighead-collage（16:9 整屏穿插）

主片是 16:9 的财经解读（织物舞台、真证据、金色大数字）。讲到**人物经历、创业故事、公司历史**（15–60 秒）时，
整屏切进 bighead-collage 做的段落——**段落本身是 16:9 横屏**，不是竖屏套窗。演完整屏切回主片。
这是章节式的穿插：两种画风各守各的规矩，边界靠铺垫和承接讲清楚，不靠画框。

## 什么时候委托

- **委托**：一个人的一生 / 一段创业史 / 一家公司的来历，文案是"他做了什么"的故事线（反常事、转折、代价）。
- **不委托**：真画面和证据（官方片、新闻原文、发布会原声）用主片自己的 `footage` / `article` / `popup`；
  数据和关系用 `number` / `chart` / `chain`。bighead 拒绝图表和坐标轴，主片拒绝拿剪贴当证据——两边别串。
- 一条主片至多一两处穿插。整条都是人物故事的话，那条片本身就该用 bighead-collage 做，不是这里。

## bighead 那边怎么做（横屏穿插模式）

在**独立工程目录**里按 bighead-collage 自己的 SKILL.md 走全流程，只改这几处：

1. `script.json` 写 `"aspect": "16:9"`（引擎和渲染都认它：stage.js 的逻辑坐标变 1920×1080，frames.mjs 出横屏）。
2. **舞台按横屏调度**：账本位横排、人物站左/右三分之一、小戏区横向展开；竖屏那套"上下堆"的分区要重排。
   动作表、事件密度（0.4–0.6 秒一个）、曲线运镜、度表照旧——那些是手艺，跟画幅无关。
3. **不加 `captions()`**：字幕由主片出（见下），段落里烧字幕会叠两层。
4. `ui_check.py` 不跑（那是抖音竖屏界面遮挡自查，横屏穿插不适用）；`verify.py --expect 1920x1080`。
5. 交片 `final.mp4`：1920×1080、带声音、verify 过。

交接简报（给 bighead 那边的开工输入）：题目和故事线（第三人称短句、第一句钩子、4.5–5 字/秒；主片文案里这几句**不念**，
主片只写铺垫句和收回句）；主角脸参考照（Commons CC BY/PD，`commons_photo.py`，记进 `SOURCES.txt`）；
事实核过；画面里不出现网址、水印、署名；生成的相像标"AI生成"。

## 收进主片

```
python scripts/insert_bighead.py <bighead工程目录> <主片目录> munger [--from 0 --to 30]
```

- 只收 1920×1080；竖屏 final.mp4 直接拒（回 bighead 改 aspect 重渲，**不要裁竖屏充横屏**）。
- 产物：`assets/clips/munger/`（30fps 横屏帧）、`counts.json` 登记、`assets/bite/munger.wav`、交接侧车。
- **bite 的 parts 按 bighead 的 timeline.json 逐句自动生成**：`[wav, 句入点, 句长, 句文字, 增益]`；
  句间静音用空字幕 part 垫住，parts 连续铺满整段（插段总长 = 段落长，画面音频不脱节）。
  主片字幕在插段期间逐句显示这段话（film_base 超 20 字自动按逗号拆短语）——全片一种字幕风格，和段落音频天然对齐。

主片 `script.json`（脚本会打印可抄的完整写法）：

```json
{"id": "s05", "text": "要看懂这笔账，得先看懂这个人。", "gap": 0.4,
 "bite": {"pre": 0.1, "post": 0.5, "parts": [["assets/bite/munger.wav", 0.15, 3.2, "1924年，芒格出生在奥马哈。", 0], …]}}
```

重跑 `timeline_stub.mjs`（或 `temp_voice.py`）。主片 `film.js`：

```js
{scene:'profile', name:'芒格', …, until:'@bite_s05', says:'铺垫：要看懂这笔账，先看懂这个人'},
{scene:'footage', clip:'munger', until:'@s06', says:'他一生只做对了一件事：反过来想',
 badge:{name:'芒格', color:'steel', at:'@bite_s05'}},
```

- 铺垫镜里这个人已经出场（profile / discs / person），穿插镜用 `badge` 把他钉在角上带进去——**带一样东西过去**，不硬切。
- 收回镜接住段落里留下的那样东西（一个数、一句话、一个人），`enter` 用续/带过/推近；或者说回主片的账（`number` / `equation`）。
- 章节感不够时，穿插前后加 `agenda` / `title` 章节卡；但边界首先靠铺垫句和承接，不靠卡。

## 为什么整屏不违反"底只有一张织物"

规矩 2 管的是主片自己的世界。穿插段是**被引用的章节**——和新闻原声画面全屏是一个性质：
有铺垫句带进去、有承接带出来、出处写进简介，观众知道这是"换了一种讲法的故事段"，不是主片舞台变了底。
条件：一段 15–60 秒、一条片至多一两处、前后都有承接。没铺垫没承接的整屏换画风才是违反。

## 声音

- bite 的每个 part 进 `mix.py` 当人声：主片配乐自动让路（sidechain）。段落自己已是成品混音（带它的音效和垫乐），
  `gain` 默认 0；`mix.py --check` 量出来和主片配音差超过 2 dB 再调。
- 段落里的音效密度是 bighead 的口味，主片别再加音效盖它；主片音效卡点在穿插前后。

## 出处与自查

- bighead 工程的 `SOURCES.txt` + 生成相像的"AI生成"标记，并进主片 `CREDITS.md` / 简介，注明"人物故事段落由 bighead-collage 制作"。
- `render.mjs --check` 无错误；穿插镜（footage 放整段）会提醒"十几秒没有新落点"——**对穿插段是预期的**：
  节奏在 bighead 段落内部（它每 0.4–0.6 秒一个事件），主片这一镜不拆。其余提醒照常处理。
- `--stills` 看三处：切进穿插那一帧（badge 在不在）、段落中段、切回那一帧的承接。
- 段落首尾帧查一遍（`strip.py`）：入点出点不压在 bighead 的换场上；压上了就 `--from/--to` 收一点重收。
- `mix.py --check`：段落响度和主片配音差在 2 dB 内。其余照 `references/review.md`。
