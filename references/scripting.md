# 选题压缩、结构化写稿与审稿（短片 / 中长片通用）

这份文档管 **站 0（选题定骨架）** 和 **站 1（口播稿撰写、初稿改写、交稿前审稿）**。
目标不是把句子润色得“像财经博主”，而是先把**核心问题、唯一隐藏变量、机制链**立住，避免信息很多但听不下去。

> 查证、来源分级与事实账本见 `references/research.md` 和 `references/facts_template.md`；开头钩子菜单见 `references/opening.md`；配音、原声剪口与混音见 `references/audio.md`。

---

## 一、先定档位：按目标时长选骨架与管线

开工前先确认目标时长（用户没说时，竖屏默认极速档，横屏默认标准短片档；用户说“深聊 / 深度 / 长片 / 5 分钟以上”走中长深度档）：

| 档位 | 目标时长 / 参考字数 | 机制链与叙事结构 | 查证与 `brief.md` | 下游管线衔接 |
|---|---|---|---|---|
| **极速 / 竖屏档** | 30–90 秒（约 120–380 字） | 反差钩子 → 1 个隐藏变量 → 2–3 步极简因果链 → 1 句反转收尾 | 轻量查核：核透主线 2–4 个核心数；`brief.md` 可选（对话确认即可） | 竖屏 `vpro` 或短横屏；不开目录、不插故事段 |
| **标准短片档** | 1.5–3 分钟（约 450–900 字） | 6 步紧凑骨架：反差钩子 → 拆掉常见误解 → 亮出隐藏变量 → 3–4 步机制链 → 1 个主案例走到底 → 反转收尾 | 标准查核：多源交叉、承重数字开页留痕；`brief.md` 可选 | 横屏默认；不开 `agenda`；沿用短片配额 |
| **中长深度档** | 5–10 分钟（约 1,500–3,000 字） | 7 段分章骨架：冷开场 → 拆浅层解释 → 窄背景与必要概念 → 隐藏变量 → 4–6 步机制链 → 多案例 / 利益方拆解（可插故事段）→ 边界风险与升级结尾 | 深度查核：**必建 `<片子>/brief.md`**；**至少查 1 条官方/权威反方或边界证据（`C01`）**；承重结论逐条开页留痕 | 启用 `agenda` 目录卡、`title` 章节卡、`story-mode` 故事段、`production.json` `chapters` + `render-chapters`；`--check` 配额按片长自动放宽 |

## 二、站 0：选题压缩协议（先定骨架，再查资料和写稿）

收到主题后，先不要直接堆资料写稿，先把题目压成三件套给用户拍板：

1. **核心因果问题**：不用名词标签（如“聊聊 AI 资本开支”），压成带张力的因果问句——**“为什么表面看起来是 Y，结果却发生了 X？”**（例：“为什么打仗了，黄金反而跌？”）
2. **唯一核心隐藏变量**：只选 1 条最能解释全局的主轴，把其余因素降级为辅助或次级约束，根治“原因一、二、三、四”的流水账。
3. **箭头机制链**（`A → B → C → D`）：短片 2–4 步，中长片 4–6 步。每一跳都要交代**谁在什么约束下改变了行为**；这条链在站 2 可直接映射为 `chain` / `flow` / `network` 视觉场景。
4. **待查核事实清单**：同步列出这条链成立必须核实的核心数据、逐字原文与（中长片必备的）反方/边界证据，直接写入 `<片子>/facts.md` 待查。

### 7 类高频财经隐藏变量速查

| 机制类型 | 适用题材 | 典型传导链 | 常见下游场景 |
|---|---|---|---|
| **口径 / 指标偏差** | GDP、通胀、失业率、估值倍数、榜单 | 选指标 → 调口径/换基准 → 对比结果翻转 → 解读完全不同 → 换一个更准的问题 | `compare` `chart` `bars` `article` |
| **把关门槛转移** | IPO 审核、牌照、行业准入、监管审批 | 分散筛选弱 → 中央把关提高门槛 → 流程变长变重 → 参与者转为优化合规 → 摩擦上升但风险下移 | `flow` `docpage` `timeline` |
| **结算层 / 基建控制** | 稳定币、支付网络、云/算力底座、应用商店 | 轨道获得信任 → 供需围绕轨道聚集 → 掌控者拿走手续费/数据/准备金 → 传统中介被绕开 → 监管重划边界 | `network` `discs` `flow` `map` |
| **杠杆 / 仓位倒逼** | 暴跌、逼空、挤兑、高息期资产抛售、融资断裂 | 重仓/高杠杆 + 期限约束 → 价格逆向波动 → 退出成本飙升 → 被迫砍仓/加码/求改规则 → 流动性踩踏 | `line` `chain` `change` `versus` |
| **资源租金陷阱** | 能源/资源国、垄断平台、高补贴行业 | 躺赚租金集中 → 权力围绕分配聚集 → 实体多元化变弱 → 外部冲击放大 → 替代/地下网络扩张 | `tree` `share` `map` `bars` |
| **可见度压力** | 财报电话会、明星公司公关、公开市场博弈 | 关注度拉满 → 声誉风险上升 → 参与者转向安全表态 → 真实信号变少 → 市场信任变脆 | `quote` `headlines` `desk` |
| **指标替代目标** | KPI 异化、增长指标、算法推荐、考核失真 | 真目标难衡量 → 找替代指标 → 全员围绕替代指标优化 → 指标好看但真目标脱钩 → 被迫换新指标 | `equation` `change` `chain` |

**站 0 交付给用户确认的内容**：2–3 个候选切口（或 1 个已明确主题的压缩方案），每条包含「核心问题 + 隐藏变量 + 机制链 + 开头钩子 + 目标时长档位（长片附章节规划）」。用户点头后再正式落稿；中长片同时把定稿骨架存进 `<片子>/brief.md`（模板见 `references/brief_template.md`）。

## 三、站 1：结构化写稿与初稿改写

### 入口 A：从主题从零写稿（5 类财经母题骨架）

选最贴近题材的母题，按目标时长决定“短片裁法”还是“中长片展开法”：

| 母题 | 适用选题 | 短片裁法（1–3 分钟） | 中长片展开法（5–10 分钟） |
|---|---|---|---|
| **指标拆解类** | GDP、CPI、估值、财报指标 | 同一指标互相打架的图开场 → 拆出关键口径 → 用 1 个例子算明白 → 告诉观众下次先问哪一句 | 冲突数据开场 → 先抛矛盾再下定义 → 用 2–3 个边界例子讲清统计边界 → 拆计算方法与跨国/跨期调整 → 回到开头升级提问 |
| **基建权力图谱类** | 稳定币、AI 算力链、支付与平台 | 巨头扎堆入场开场 → 点破“不只是炒作” → 画出资金/权力环流 → 落到谁赚确定钱、谁扛风险 | 多方动作堆叠开场 → 拆基建层定义 → 逐一画清各方账本（手续费/数据/现金流）→ 传统巨头与监管反制 → 留在未解的结构张力 |
| **制度流程类** | IPO、监管审批、招投标、审计 | 从 1 个真实主角/公司卡住的瞬间切入 → 点破核心把关逻辑 → 3 步流程说明为何慢 → 结论收束 | 主角/事件入场 → 对比不同市场谁承担筛选成本 → 逐关过流程节点 → 把规则翻译成各方激励 → 穿插人物/公司故事段（`story-mode`）→ 退回制度设计 |
| **市场事故复盘类** | 闪崩、逼空、挤兑、资产异常波动 | 事故数字砸开场 → 倒回仓位/利率约束 → 3 步推演被迫动作 → 一句话看懂底层规律 | 事故与筹码开场 → 倒回失衡起点 → 拆杠杆/期限/流动性约束 → 还原被迫决策点（可用 `story-mode`）→ 监管或规则介入 → 留给观众的机制教训 |
| **国家 / 行业深潜类** | 宏观经济、关税、制裁、产业周期 | 反常识新闻与数据反差开场 → 只补 1 句必要背景 → 1 条核心约束串起 3 步传导 → 现实落点 | 头条与深层反差开场 → 只补解释当下必需的历史背景 → 亮出核心制度/租金/约束 → 拆解各部门与利益方 → 结合当前指标与反方边界 → 给出情景推演（不做拍脑袋预测） |

### 入口 B：长研报 / 文章 / 用户初稿 → 诊断与压缩改写

当用户贴进一篇长文、研报或自己写的口播初稿时，先诊断结构再改稿，固定输出五块：
1. **一句话诊断**：直指最致命的结构问题（例如“像资料卡，堆了 5 个并列原因，但没说清谁推动了谁”）。
2. **优先级最高的 3–5 个问题**：按“问题 → 变量 → 机制链 → 事实冗余 → 口语”排序，不先抓语病。
3. **重建后的核心问题 + 隐藏变量 + 机制链**（标明按短片还是中长片压缩）。
4. **改写版口播稿**（长片带章节标题，标注拟用 `agenda` 或 `story-mode` 的段落）。
5. **事实与证据缺口**：列出原文没给来源、单源或需要补查一手（及反方）的点，转入 `facts.md`。

### 默认口播质感：松弛聊天感（像跟朋友把一笔大账算明白）

不管短片还是中长片、有无真人出镜，默认都按这套口播质感写（用户明确要求其他口吻时再切）：

1. **1 个贯穿全片的生活化算账比喻**：把宏观/财务概念缩成一个普通人一听就懂的日常场景反复用（例如把低息国债比作“免息期信用卡”，把名义 GDP 扩张拉低负债率比作“年薪涨了，房贷占收入比例自然降了”）；比喻要短、服务于机制，不喧宾夺主。
2. **把研报和统计术语全翻成人话**：少念“预算概算要求 / 实际工资同比 / 分母效应 / 资产定价”这类书面播报词，改成“刚递上去的新预算申请单 / 扣掉涨价后真到手的购买力缩水 / 年薪涨了房贷占比就降了”。
3. **面对镜头的呼吸感与互动节奏**：每章留 1–2 处轻巧停顿、自然反问或情绪落差（“听着挺吓人对吧？先别急，把账本翻到背面看一眼…”），避免从头到尾端着念稿。
4. **底线不变**：松弛不等于水词，数字、双口径与事实精度不打折，依然严守零 AI 腔套话，也不抄任何博主的固定口头禅。

### 写稿六条硬纪律

1. **先抛矛盾，再下定义**：不在开头背概念；等观众因为反差产生疑问时，再在那一刻给最窄的必要定义。
2. **把抽象名词改写成动作**：少写“效率提升、结构优化、宏观承压”，改写为**“谁（公司/央行/散户/监管）+ 面对什么约束 + 被迫做出什么决定”**。
3. **不推动机制链的事实一律删掉**：数字是转折点不是装饰；一个案例能走到底就反复用同一套人物和数字，别每段换一批新角色增加认知负荷。
4. **口语、第一人称、去 AI 腔**：像跟朋友把一笔账算明白；句句接住上一句；**严禁**“值得注意的是 / 总而言之 / 综上所述 / 众所周知 / 毋庸置疑 / 不难发现 / 赋能 / 全方位 / 一站式 / 打造闭环”等套话，也**不抄**固定口头禅。
5. **数字与账本强绑定**：台词里出现的每一个数字必须对应 `facts.md` 编号；数字口播写法与上屏写法一致（不擅自换算）；来自公司自述的份额/预测必须显式交代口径（如“按它财报自己算的”）。
6. **为声音与画面留接口**：
   - 准备插当事人原声（`bite`）前，前一句必须写铺垫交代人名和性质（见 `references/audio.md` 与规矩 34）。
   - 开头第一句必须在 0.5 秒内开口并直接给“料”（见 `references/opening.md`）。
   - 中长片每隔 45–60 秒设计一次认知微反转或进入新章节，避免平铺直叙。

## 四、站 1 出口门禁：8 维审稿清单与落盘

全文交给用户审阅之前，先按下面 8 项自检；**改稿必须按优先级从上往下修**（先修结构，最后才改措辞）：

| 优先级 | 检查维度 | 合格标准 | 常见病与修法 |
|---|---|---|---|
| 1 | **核心问题张力** | 开头 1–2 句抛出真实反差或困惑，不是空泛名词标签 | 只是“今天聊聊 X” → 改写成“为什么 Y 却发生 X” |
| 2 | **隐藏变量统摄力** | 1 个主变量能解释全稿大部分走向 | 塞了四五个并列原因 → 拎出最底层的 1 个，其余降为支撑或删掉 |
| 3 | **机制链闭环** | 每一步因果相连、无跳步，动机和后果清楚 | 只有起点和结论、中间靠“所以”硬跳 → 补出中间的约束与被迫行为 |
| 4 | **段落递进** | 每一段回答一个问题，同时自然勾出下一段的问题 | 段落调换顺序也不影响阅读 → 重排或删掉支线 |
| 5 | **认知负荷控制** | 专有名词只在需要的瞬间出现；不一次堆一堆人名和年份 | 开头一口气甩 5 个术语 → 删掉与机制无关的术语，留到对应步骤再讲 |
| 6 | **证据与反方纪律** | 数据、案例、推算、自述口径分清；全稿数字挂 `facts.md`；中长片含至少 1 条权威反方/边界 | 拿单一媒体或自媒体下铁论 → 标单源/回改措辞，或补查一手 |
| 7 | **口语可读性** | 读出来顺口、短句好断气，无 AI 腔套话，原声前有铺垫句 | 书面长难句、排比总结 → 拆成口语短句；可用 `facts_check.py` 扫套话 |
| 8 | **结尾反转** | 机制讲完后，回头看开头的问题有“原来如此”或问题升级感 | 结尾只把前面复述一遍 → 改写成回扣开头的认知更新或边界提醒 |

### 定稿落盘到 `script.json`（及长片 `chapters`）

用户点头定稿后（点头前不做正式配音；定稿后不擅自改口播）：
1. 按 `scripts/temp_voice.py` 格式拆句写入 `<片子>/script.json`：
   - 每句一个唯一 `id`（如 `b01`、`b02`），正文写 `text`，句间停顿 `gap`（常规 `0.35`，换段/换章 `0.5`），`pre ≤ 0.35`。
   - 数字或英文易读错时用 `say` 单独写给 TTS 的读法，不改 `text`。
   - 原声插段在铺垫句下挂 `bite`；片名位置写 `title`。
2. **中长片**同步把各章名称与起止句边界记入 `<片子>/production.json` 的 `chapters`（时间待站 4 时间线生成后填入），方便后续走 `agenda` 目录与 `video_pipeline.py render-chapters` 分章预览。
3. 跑一次 `python scripts/facts_check.py <片子>`，确认账本格式、链接、日期、AI 腔提醒与（中长片）反方/开页留痕无遗漏。
